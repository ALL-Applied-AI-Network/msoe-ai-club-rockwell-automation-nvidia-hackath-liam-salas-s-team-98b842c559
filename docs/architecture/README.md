# Architecture tour

FluidMix is the product at the centre of this repository: it turns vial imagery and
recipe context into measured evidence, a deterministic keep/discard decision, and an
evidence-cited explanation. The source tree groups that product as inward-facing onion
rings under `src/fluidmix/`.

## Product rings

Dependencies point inward, from orchestration toward small, stable building blocks:

1. `fluidmix.core` defines contracts, policy, and repository paths. Its target boundary
   is pure code with no file, database, subprocess, or network access, except for the
   specification-mandated strict snapshot helpers in `fluidmix.core.io`.
2. `fluidmix.colour` contains colour conversion, statistics, colour difference, and
   expected-colour math.
3. `fluidmix.perception` produces liquid masks and camera-derived fill state, while
   `fluidmix.measurement` turns masked imagery into stage measurements.
4. `fluidmix.decision` makes deterministic keep, discard, or insufficient-evidence
   decisions. `fluidmix.explanation.template` renders guarded, evidence-cited text.
5. `fluidmix.storage`, `fluidmix.memory`, and `fluidmix.explanation.vlm` provide outer
   adapters for persistence, evidence retrieval, and model-backed explanations.
6. `fluidmix.pipeline` is the outermost product ring. Its `service` package exposes the
   live HTTP/SSE runner and wires file, V4L2, and RTSP inputs through the frozen pipeline.

Import-linter contracts and an inner-ring purity check enforce these directions. The
runner keeps its accepted model, tracker, decision, and guard freezes while allowing one
source-processing path for any supported input.

## Neighbouring packages

- `src/evaluation/` contains RCA-bench and scoring code. It may evaluate the product,
  but product and twin code must not import it.
- `src/twin/` contains the Part A simulator, scene, rendering, cohort, and post-render
  tooling. It is independent from the product package.
- `cli/` contains runnable commands grouped to mirror product, twin, and evaluation
  responsibilities. Importable behavior remains in `src/`.
- `tests/` mirrors the source-package layout.
