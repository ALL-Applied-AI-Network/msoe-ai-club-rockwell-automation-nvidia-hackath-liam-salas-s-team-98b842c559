# Evaluation and frozen partitions

No detector scoring pipeline is implemented. The fit script reports clean-vial color
prediction error only. Synthetic math checks are not real generalization evidence.

## Partition rules

Train learned models on twin synthetic data only. Test sets are also generated with the twin;
real videos serve only for occasional validation (scope decision of 2026-10-15/16 in [data](data.md)).

T-300 is unavailable for the whole hackathon (organizer feedback, Owen, chat, 2026-10-14), and the
dataset README says T300 was intermittent/out of service and not used during collection. No
calibration, validation or test partition may contain or depend on T-300 data; real recipes use
only T-100, T-200 and T-400.

## Partitions v2 (INN-7 T4, 2026-10-16)

Decisions (Liam, 2026-10-16): twin recipes are generated at random for training, validation
and test. The 10 real video-5 recipes are reserved for the final real-video validation and
never rendered, so the real check runs on recipes no model has seen. The "near" volume threshold
is 3 mL per tank (changed from 5 mL, decided by Liam 2026-10-16).

Generated by `scripts/make_splits.py` (spec version v2, seed 20261016); checked by
`scripts/check_leakage.py`, which also runs in the test suite.

Version history: v1 (git tag `inn-7-splits-v1`: near threshold 5 mL, ratio buffer only; train 266,
val 31, test 23, buffer 48) was superseded by v2 because an independent review found that all 23 v1
test recipes were within 5 mL per tank of a train recipe.

| File | Content |
|---|---|
| `data/sim_split_spec.json` | Rules, plant limits, reserved real recipes, seed ranges, counts |
| `data/sim_recipes.csv` | Every twin recipe and its role |
| `data/sim_transitions.csv` | One carryover pair (previous → next recipe) per recipe, inside one role |
| `data/real_check_frames.csv` | Every video-5 vial_fill still, eligibility and reason |
| `data/real_check_windows.csv` | Per video-5 vial: final-mixture frame window, eligibility and reason |

- **Twin recipes:** every recipe on a 5 mL grid (each tank unused or 10–60 mL) with at least two
  tanks, 30–80 mL total and at most 50 mL from T-200. That gives 514 recipes. 76 are dropped
  because they are near a real recipe: within 3 mL on every tank, or within 0.05 of its volume
  fraction on every tank. 438 remain, in 92 ratio cells.
- **Role unit:** a mixture-ratio cell (volume fractions rounded to 0.1). The colour depends mostly
  on the ratio, so recipes with the same ratio cell never sit in two roles. Neighbouring cells can
  still hold close recipes, so a val recipe becomes `buffer` (never rendered) if it is within 0.03 in
  fraction on every tank, or within 3 mL on every tank, of a train recipe; a test recipe becomes
  `buffer` if it is that close to a train or val recipe. Result: train 315, val 30, test 35,
  buffer 58. Carryover pairs: one per used recipe, so 380 (train 315, val 30, test 35).
- **What the 3 mL rule really does:** every recipe sits on the 5 mL grid, so two different recipes
  always differ by at least 5 mL on some tank. A 3 mL threshold therefore only catches identical
  per-tank volumes. Separation between roles rests mainly on the ratio-cell assignment and the
  0.03 ratio buffer. All 35 v2 test recipes are still within 5 mL per tank of some train recipe
  (measured on `data/sim_recipes.csv`). Accepted (Liam, 2026-10-16): a test recipe only has to
  differ from every train recipe, not be far from it.
- **Render seeds:** train 0–999,999, val 1,000,000–1,999,999, test 2,000,000–2,999,999. Every frame
  of one rendered sequence stays in its recipe's role.
- **Leakage check:** fails if a recipe, a ratio cell or a carryover pair crosses roles, if two used
  roles have recipes within 0.03 in fraction or within 3 mL on every tank, if a twin recipe is near
  a real recipe, or if seed ranges overlap. It reports, but does not fail on, cross-role pairs under
  the looser near rule (3 mL on every tank or 0.05 in fraction): 119 pairs in v2.
- **Render manifest check (`--manifest`, hardened 2026-10-16):** a render manifest must have the
  columns `path`, `sim_recipe_id`, `role` and `seed`. The role is looked up in `data/sim_recipes.csv`,
  so unknown recipes, `buffer` recipes and rows whose role disagrees fail. Each seed must sit in its
  role's range and belong to one role only. Every listed file that exists is hashed, and fails if
  its bytes match a real dataset file in `data/dataset_manifest.csv`; a listed file that does not
  exist fails unless `--allow-missing` is passed. Across all manifests passed together, a file
  (same resolved path) or a byte-identical copy (same SHA-256) listed under two roles fails; reuse
  inside one role is allowed. Limit: it compares bytes, so a re-encoded or resized copy of a real
  image or another role's render is not caught, and manifests checked in separate runs are not
  compared with each other.
- **Independence:** the rules guarantee that no recipe, ratio cell, carryover pair or seed range is
  shared across roles, and that no two recipes in different used roles are within 0.03 in fraction
  or 3 mL on every tank. They do not guarantee distant recipes: neighbouring recipes 5 mL apart can
  sit in different roles, so test recipes are close relatives of train recipes. The twin test set
  comes from the same twin, so it measures generalization inside the simulation only. Video 5 is the
  only evidence about the real line, and with 28 eligible vials it is a check, not a benchmark.
- **Changing the split:** bump the spec version and record why. Do not edit roles after any test
  scoring.

## Deferred: absorbance calibration

Absorbance values will come from a separate model; that decision is deferred (2026-10-16). No
absorbance is calibrated from twin renders, whose colours are set by our own variant layer. The
earlier leave-one-recipe-out plan for fitting tank absorbance on real vials is on hold. If real
vials are ever used to fit anything, those vials leave the real check, are listed with the role
`calibration`, and the fit is frozen before the check is scored. The full-data diagnostic fit in
`scripts/fit_absorbance_video5.py` is not a deployable calibration and still gives negative
absorbance.

## Pre-registration (INN-7 T6, 2026-10-16, before any tuning)

**Units.** A vial is one fill. A transition vial is the first vial after a recipe change. A repeat
vial is position 2 or 3 in a run of the same recipe. See `data/video5_transitions.csv` and
[labels](labels.md).

**Defects in the twin** (definitions fixed now; numbers set on val and frozen before test scoring):
- wrong volume: any tank dispenses at least `wrong_volume_ml` away from the recipe;
- carryover: the residue fraction from the previous recipe is at least `carryover_fraction`;
- other injected faults are added only with a written definition before they are rendered.
Twin labels come from the render parameters, never from a detector's colour score.

**Real check procedure.** For each eligible vial, the system predicts the colour difference (ΔE)
between the vial and the clean recipe colour, from the recipe and the previous recipe, before
the fill is measured. If the predicted ΔE exceeds the threshold τ, set on twin val, the physics
model recommends an action. Video 5 has no defect labels, so the check compares the prediction with
the measured ΔE of the same vial. It tests whether the prediction agrees with the line, not
detection accuracy, because the comparison value is itself colour-derived.

**Eligibility.**

| Set | Eligible | Excluded |
|---|---|---|
| Twin test | all 35 test recipes and their 35 carryover pairs | buffer recipes; the first vial of each rendered run is excluded from carryover metrics |
| Real check (vials) | 28 vials: 2–9 and 11–30; 8 transition, 20 repeat | vial 1 (previous recipe unknown); vial 10 (window 2 frames) |
| Real check (stills, labels only) | 716 of 845 (447 during a fill, 269 between fills) | 114 within 2 s of a fill boundary, 14 of vial 1, 1 before the video |

**Final-mixture window (measured 2026-10-16).** Tanks dispense one after another (T200, then T400,
then T100), so the vial shows its final mixture only after the last tank stops. The filled vial then
leaves the view quickly: its cart starts moving 0.47–5.27 video seconds after the labelled fill end
(median 2.18 s), checked by eye on vials 6, 10 and 14. Stills, about 1.65 video seconds apart, are too
sparse: of vials 1–25, 7 have no still in the window, 17 have one and 1 has two. So the real
check measures video frames, which also covers vials 26–30, where stills are missing.

- Window per vial: from `end_s` + 0.3 s (last drops fall) to 0.1 s before the cart moves.
  The cart counts as moving at the first frame whose mean grey difference from the `end_s` + 0.3 s
  frame exceeds 6 levels (160×120, clock rows excluded). Fewer than 3 frames makes a vial ineligible.
- Written by `scripts/real_check_windows.py` to `data/real_check_windows.csv`: 7–146 frames per
  eligible window.
- Vial colour: the median colour inside the liquid region of each frame, then the median over the
  window's frames.
- Known limits: `end_s` was placed by eye, so a window may start while the last drops still fall,
  with about ±1–2 s error seen on vial 25. The clear T100 goes in last and may not be fully mixed
  within 2 s, so the colour can be layered. Both are frozen as is; report them with the result.

**Abstentions** (no prediction; counted and reported, never scored as correct): no liquid region
found or region below a minimum area; more than a set share of liquid pixels saturated or
underexposed; absorbance negative or outside the model's valid range; the frame is uncertain under
[labels](labels.md).

**Metrics and denominators.**

| Metric | Set | Denominator |
|---|---|---|
| Defect recall, per defect type | twin test | eligible defective vials that did not abstain |
| False alarm rate | twin test | eligible clean vials that did not abstain |
| Residue fraction error | twin test | vials with injected carryover |
| ΔE prediction error (predicted vs measured) | twin test; real check (window frames), reported apart | eligible vials that did not abstain |
| Flag agreement (predicted ΔE > τ vs measured ΔE > τ), 2×2 counts | real check | eligible vials that did not abstain |
| Abstention rate | both | all eligible vials |

Baselines on the same eligible vials: the first-vial rule (flag every transition vial), a
vision-only fixed-threshold colour check, and a drainage-only tank model (see the matched baseline
table). The full method must beat the vision-only and drainage-only baselines to show that each
part adds value. The plant's Teledyne colour check is not a baseline for now (decided
2026-10-16): it is the system being replaced, the organizers supplied no outputs from it, and it
only asks whether a colour is known, not whether the vial matches its recipe or whether carryover
will affect the next one. Its outputs may be gathered later for context.
Thresholds and model/config IDs are chosen on twin val only, then frozen and tagged before test
scoring. Report counts with every percentage.

## Labels and denominators

Committed CSVs have 30 vials in 10 recipe groups. They expose nine transitions between
groups (`data/video5_transitions.csv`). Vial 1 has no recorded previous recipe. The inherited
"10 changeovers, 8/10" claim includes an initial batch and was based on rough color comparisons;
it is not an independently verified defect-label set. See [labels](labels.md) and [data](data.md).

## Matched baseline comparison

| Baseline | Behavior | Current evidence |
|---|---|---|
| First-vial rule | Flag every eligible first vial after a known recipe change | Rule defined; independent defect scoring pending |

A later, separate model is proposed to estimate the volume drawn from each tank in each video
frame from vision. It is not a baseline and is not implemented.
